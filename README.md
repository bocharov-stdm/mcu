# mcu

Лабораторные работы по микроконтроллерам на **Raspberry Pi Pico** (RP2040,
Pico SDK, C). Шесть заданий идут по возрастанию сложности: от мигания
светодиодом до готового устройства — метеостанции с датчиком BME280 и
TFT-дисплеем ILI9341, которой можно управлять командами с компьютера.

| # | Папка | Тема | Периферия |
|---|-------|------|-----------|
| 1 | [01-blink](01-blink/) | Мигание светодиодом | GPIO |
| 2 | [02-printf](02-printf/), [02-echo](02-echo/), [02-on-off](02-on-off/), [02-control](02-control/) | Ввод/вывод через USB, консоль команд | USB CDC, GPIO |
| 3 | [03-adc](03-adc/) | Аналого-цифровой преобразователь, телеметрия | ADC, встроенный датчик температуры |
| 4 | [04-bme](04-bme/) | Датчик температуры, давления и влажности | I2C, BME280 |
| 5 | [05-display](05-display/) | Графический дисплей | SPI, ILI9341 320×240 |
| 6 | [06-device](06-device/) | Итоговое устройство: метеостанция | I2C + SPI |

## Структура репозитория

```
01-blink/          задание 1
02-*/              задание 2 (четыре подзадачи)
03-adc/            задание 3
04-bme/            задание 4
05-display/        задание 5
06-device/         задание 6
libs/
  bme280-driver/   драйвер датчика BME280
  ili9341-driver/  драйвер дисплея ILI9341, графика и шрифт
  protocol/        разбор и выполнение текстовых команд
```

Каждое задание — отдельный CMake-проект со своими `CMakeLists.txt`,
`pico_sdk_import.cmake` и линкер-скриптом `memmap_rp2040.ld`. Задания 4–6
подключают общие библиотеки из [libs/](libs/) через `add_subdirectory`.

## Как устроена прошивка (задания 2–6)

Начиная с `02-control` прошивка построена как **суперцикл без блокировок**:
в `main()` крутится бесконечный цикл, который по очереди вызывает
обработчики независимых «задач». Ни одна задача не использует `sleep_ms`
в рабочем режиме — время отслеживается через `time_us_64()`, поэтому
светодиод мигает, датчик опрашивается и консоль отвечает одновременно.

```c
while (1)
{
    led_task_handle();                           // светодиод
    protocol_task_handle(stdio_task_handle());   // консоль команд
    bme280_task_handle();                        // поток телеметрии
}
```

| Задача | Что делает |
|--------|-----------|
| `stdio-task` | Посимвольно читает ввод с USB, показывает эхо, по `Enter` отдаёт готовую строку (до 127 символов, `Backspace` поддерживается) |
| `protocol-task` | Делит строку на имя команды и аргументы, ищет команду в таблице `api_t` и вызывает её обработчик |
| `led-task` | Светодиод на GP25: выключен / включён / мигает с заданным периодом |
| `adc-task` | Задание 3: раз в 100 мс печатает напряжение и температуру |
| `bme280-task` | Задания 4, 6: раз в 100 мс печатает температуру, давление и влажность |

Команды описываются одной таблицей — чтобы добавить новую, достаточно
написать обработчик и добавить строку:

```c
api_t device_api[] =
{
    {"help",    help_callback,    "print this help message"},
    {"version", version_callback, "get device name and firmware version"},
    ...
    {NULL, NULL, NULL},
};
```

### Общие команды

Есть во всех заданиях с 3 по 6 (в `02-control` — те же по смыслу, но
с другими именами: `on`, `off`, `blink`, `blink_set_period_ms`).

| Команда | Описание |
|---------|----------|
| `help` | список всех команд |
| `version` | имя устройства и версия прошивки |
| `led_on`, `led_off`, `led_blink` | управление светодиодом |
| `set_period <мс>` | период мигания (в 06-device — `led_period`) |
| `mem <адрес>` | прочитать 32-битное слово по адресу, например `mem 40000000` |
| `wmem <адрес> <значение>` | записать слово по адресу (адрес кратен 4) |

## 1. Мигание светодиодом — `01-blink`

Первая программа для микроконтроллера: настройка GP25 на выход и
бесконечный цикл `gpio_put` + `sleep_ms`. Светодиод горит 250 мс и гаснет
на 1 с.

## 2. Ввод/вывод и консоль команд — `02-*`

Четыре подзадачи, которые шаг за шагом приводят к консоли устройства.

- **[02-printf](02-printf/)** — вывод через USB (`stdio_init_all`,
  `printf`) и знакомство с картой памяти RP2040. Раз в секунду печатает
  адреса и значения переменной на стеке, глобальной переменной, переменной
  в куче, константы и строки, читает регистр периферии `0x40000000` (chip
  id) и первые байты функции `main`. Память из кучи намеренно не
  освобождается — это часть задания: видно, как растут адреса.
- **[02-echo](02-echo/)** — читает символ с USB и печатает его и его код.
- **[02-on-off](02-on-off/)** — светодиод управляется одиночными символами:
  `e` — включить, `d` — выключить, `v` — версия. Работа со светодиодом
  вынесена в модуль `led/`. Скрипты `on_off.py` и `led.py` — черновики
  хостовой части, не доделаны.
- **[02-control](02-control/)** — полноценная консоль: строки вида
  `команда аргументы`, табличный диспетчер, мигание без блокировок.
  Команды `mem`/`wmem` проверяют выравнивание адреса и разрешают доступ
  только к SRAM (`0x20000000–0x20042000`) и периферии
  (`0x40000000–0x50000000`).

## 3. АЦП и телеметрия — `03-adc`

Чтение аналогового напряжения и встроенного датчика температуры RP2040.

- Напряжение измеряется на **GP26 (ADC0)**, диапазон 0–3,3 В, АЦП 12-битный:
  `U = код · 3,3 / 4095`.
- Температура — канал 4 (встроенный датчик), пересчёт по формуле из
  документации RP2040: `T = 27 − (U − 0,706) / 0,001721`.

| Команда | Описание |
|---------|----------|
| `get_adc` | напряжение на GP26, В |
| `get_temp` | температура кристалла, °C |
| `tm_start` / `tm_stop` | включить / выключить поток телеметрии: раз в 100 мс строка `напряжение температура` |

Скрипты на Python (порт `COM13` задан в коде):

- [get_adc.py](03-adc/get_adc.py) — сам опрашивает плату командами
  `get_adc` / `get_temp` и строит графики;
- [get_telemetry.py](03-adc/get_telemetry.py) — включает `tm_start`,
  читает поток, по `Ctrl+C` выключает его и строит графики напряжения и
  температуры от времени.

## 4. Датчик BME280 — `04-bme`

Датчик температуры, давления и влажности Bosch BME280 на шине **I2C1**
(100 кГц, адрес `0x76`). Драйвер вынесен в
[libs/bme280-driver](libs/bme280-driver/) и не зависит от Pico SDK:
функции чтения и записи по I2C передаются в `bme280_init()` указателями,
поэтому драйвер можно перенести на другой микроконтроллер.

При инициализации драйвер проверяет ID чипа (`0x60`), включает нормальный
режим измерений и читает калибровочные коэффициенты. Значения в
физических единицах считаются по формулам компенсации из datasheet.
Температура и давление читаются полностью (20 бит), влажность — 16 бит.

| Команда | Описание |
|---------|----------|
| `read_regs <рег> <N>` | прочитать N регистров подряд, например `read_regs 88 1A` |
| `write_reg <рег> <значение>` | записать регистр |
| `temp_raw`, `pres_raw`, `hum_raw` | «сырые» значения АЦП датчика |
| `temp`, `pres`, `hum` | температура (°C), давление (гПа), влажность (%) |
| `tm_start` / `tm_stop` | поток телеметрии: раз в 100 мс строка `температура давление_Па влажность` |

[graphic4.py](04-bme/graphic4.py) читает поток с `COM14` и по `Ctrl+C`
строит три графика. Поток нужно заранее включить командой `tm_start`.

## 5. Дисплей ILI9341 — `05-display`

Цветной TFT-дисплей 320×240 на контроллере ILI9341, шина **SPI0**
(10 МГц). Драйвер в [libs/ili9341-driver](libs/ili9341-driver/) тоже
отвязан от железа: SPI, линии CS/DC/RESET и задержка передаются через
структуру `ili9341_hal_t`.

Возможности драйвера: заливка экрана, пиксель, линия (алгоритм
Брезенхэма), прямоугольник и закрашенный прямоугольник, текст
моноширинным шрифтом JetBrains Mono 8, поворот экрана. Цвета хранятся в
формате RGB565, макрос `RGB888_2_RGB565` переводит в него привычный
`0xRRGGBB`.

При старте рисуется тестовая картинка. Команды (цвет — `0xRRGGBB`):

| Команда | Пример |
|---------|--------|
| `disp_screen [цвет]` | `disp_screen 0x0000FF` — залить синим, без аргумента — чёрным |
| `disp_px x y цвет` | `disp_px 100 100 0xFF0000` |
| `disp_line x0 y0 x1 y1 цвет` | `disp_line 0 0 319 239 0xFFFF00` |
| `disp_rect x y w h цвет` | `disp_rect 10 10 100 50 0xFFFFFF` |
| `disp_frect x y w h цвет` | `disp_frect 10 10 100 50 0x00FF00` |
| `disp_text x y цвет текст` | `disp_text 10 10 0xFFFFFF Hello, World!` |

[disp_image.py](05-display/disp_image.py) выводит на дисплей любую
картинку: подгоняет её под 320×240 (с полями или с обрезкой, вертикальные
поворачивает) и отправляет попиксельно командами `disp_px`. Это 76 800
команд, поэтому вывод занимает несколько минут.

```sh
python disp_image.py photo.jpg --port COM15
```

## 6. Метеостанция — `06-device`

Итоговое задание объединяет BME280 и дисплей в одно устройство. Раз в
заданный период (по умолчанию 1 с) прошивка измеряет параметры воздуха и
перерисовывает экран:

- температура, влажность и давление — числом и полоской-индикатором;
- цвет показывает, в норме ли значение: например, температура голубая
  ниже 18 °C, зелёная при 18–26 °C и красная выше 26 °C;
- текущий период измерений и состояние RUN / STOP;
- график температуры по последним 60 измерениям (кольцевой буфер).

Доступны все команды из заданий 4 и 5, а также:

| Команда | Описание |
|---------|----------|
| `tm_start` / `tm_stop` | запустить / остановить измерения; одновременно включается поток телеметрии в консоль, совместимый с `graphic4.py` |
| `tm_period <мс>` | период измерений, не меньше 500 мс |
| `led_period <мс>` | период мигания светодиода |

## Подключение

Всё питание — от 3,3 В платы Pico (вывод 3V3), общая земля GND.

**BME280 (задания 4, 6)**

| BME280 | Pico |
|--------|------|
| SDA | GP14 |
| SCL | GP15 |
| VCC | 3V3 |
| GND | GND |

**ILI9341 (задания 5, 6)**

| ILI9341 | Pico |
|---------|------|
| SDO (MISO) | GP4 |
| SCK | GP6 |
| SDI (MOSI) | GP7 |
| DC | GP8 |
| RESET | GP9 |
| CS | GP10 |
| LED | 3V3 |
| VCC | 3V3 |
| GND | GND |

**АЦП (задание 3)** — измеряемое напряжение (0–3,3 В) на GP26.

## Сборка и прошивка

Нужны [Pico SDK](https://github.com/raspberrypi/pico-sdk), CMake ≥ 3.15 и
тулчейн `arm-none-eabi-gcc`. Переменная окружения `PICO_SDK_PATH` должна
указывать на папку с SDK.

Каждое задание собирается отдельно из своей папки:

```sh
cd 06-device
cmake -B build
cmake --build build -j4
```

На Windows с `make` из MinGW генератор указывается явно:

```sh
cmake -B build -G "MinGW Makefiles"
```

В `build/` появится файл `.uf2`. Чтобы прошить плату, подключите её по USB
с зажатой кнопкой **BOOTSEL** — появится диск `RPI-RP2`, скопируйте на
него `.uf2`. Папки `build/` в git не хранятся (см. `.gitignore`).

## Работа с устройством

Плата видна как виртуальный COM-порт (USB CDC). Подключиться можно любым
терминалом — PuTTY, встроенный монитор VS Code, `screen` или `picocom` на
Linux (`/dev/ttyACM0`). Команды вводятся строкой и отправляются `Enter`;
для начала наберите `help`.

Для Python-скриптов нужны пакеты:

```sh
pip install pyserial matplotlib pillow
```

Номера COM-портов в скриптах (`COM13`, `COM14`, `COM15`) — с машины, на
которой делались задания; поменяйте их на свои (порт видно в диспетчере
устройств Windows).
